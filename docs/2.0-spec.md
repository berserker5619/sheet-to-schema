# sheet-to-schema 2.0

2.0 makes sheet-to-schema a set of functions. The package reads, matches, validates and
streams. Apps own routes, storage, jobs and queues. The recommended server pattern becomes
background imports with polling, built from the functions.

Status: **2.0.0-rc.1**. Decisions D1–D7 are settled; this document records them with
exact signatures, and is changed only through the revision log at the end.

Related: [api-audit.md](api-audit.md) (step 1, every export and who uses it), the 1.x
[CHANGELOG](../CHANGELOG.md), and [CONTRIBUTING](../CONTRIBUTING.md) for the release lines.

## 1. Decisions

| | Decision |
| --- | --- |
| D1 | Remove `createImportRouter`, its @internal hooks, and the `express` optional peer. Remove HTTP-only helpers the audit shows nothing outside the router uses (§3). |
| D2 | `runImport` gains `signal?: AbortSignal` (§2.1). |
| D3 | `runImport` gains `onProgress` (§2.1). |
| D4 | `runImport`'s `grouping` defaults to `true`. `group.contiguous: false` is still refused (`INVALID_PLAN`, `PLAN_GROUP`, reason `non-contiguous`). |
| D5 | Unrecognised binary input is refused with `UNSUPPORTED_FORMAT` by `readSheet`, `readSheetFile`, `readCsvFile`, `previewSheet` and `runImport`, defined in §4.2. Every CSV variant 1.x accepts is still accepted. |
| D6 | Out of scope for 2.0, for later additive minors: a zero-dependency xlsx reader; choosing the header row or the sheet; a JSZip inflate fallback for older browsers. Routes, storage, a job system or queues in the package: never. |
| D7 | A 1.x line for Dynamic Entity 3.x: branch `1.x` from `v1.3.0`; `v1.*` tags publish under the dist-tag `release-1.x`, never `latest` or `next`. Done in step 0 (`scripts/release-publish.mjs`, proven by `npm run check:release`). |

Decisions taken at the audit (step 1, 2026-10-19):

- `ImportLimits.idleTimeoutMs` stays and is enforced by `receiveUpload` itself (§4.3).
  `ImportLimits.totalTimeoutMs` is removed; a whole run is bounded with
  `signal: AbortSignal.timeout(ms)`. **No limit may remain that nothing enforces.**
- `readPlanField`, `toErrorBody`, the wire types and `planForServer` stay.
- `templateOf` and `templateFilename` move from `router.ts` to `write-template.ts`; still exported
  from `/node`.
- `SERVER_FEATURES` stays, moved to the main entry next to `planForServer`: it is a capability
  vocabulary, not HTTP. `/node` no longer exports it.

## 2. API changes

### 2.1 `runImport` (`sheet-to-schema/node`)

```ts
export interface ImportProgress {
  /** Bytes consumed from the input so far. Equals the input's size once the run has finished. */
  bytesRead: number;
  /** Data rows read so far. Equals the result's `rowsRead` once the run has finished. */
  rowsRead: number;
}

export interface RunImportOptions<TMeta = unknown, TCtx = unknown> {
  stream: ByteSource;
  filename?: string;
  plan: unknown;
  adapter: SchemaAdapter<TMeta, TCtx>;
  ctx: TCtx;
  decimal?: '.' | ',';
  dateOrder?: DateOrder;
  onBatch?: OnBatch;
  /** Default `true` in 2.0 (was `false`). */
  grouping?: boolean;
  limits?: Partial<ImportLimits>;
  /** New in 2.0 (D2). */
  signal?: AbortSignal;
  /** New in 2.0 (D3). */
  onProgress?: (progress: ImportProgress) => void;
}

export function runImport<TMeta, TCtx>(options: RunImportOptions<TMeta, TCtx>): Promise<ImportRunResult>;
```

`ImportRunResult`, `BatchInfo`, `OnBatch`, `previewSheet` and `SheetPreview` are unchanged.

**`signal` (D2).**

1. If the signal is already aborted when `runImport` is called, it rejects without reading a
   byte, and the source is destroyed.
2. When the signal aborts during a run, `runImport` stops reading at once (a read waiting on a
   stalled source is abandoned, not awaited) and starts no new batch.
3. It never interrupts an `onBatch` that is running. It waits for that call to settle; that batch
   counts as imported.
4. It then rejects with `ImportError` code `ABORTED`, message `The import was cancelled.`,
   `details: { rowsRead, imported, failed }` (the counts at the moment it stopped), and
   `cause: signal.reason` (so a timeout, `AbortSignal.timeout`'s `TimeoutError`, can be told from
   a cancel).
5. The source stream is destroyed whenever the run is aborted.
6. An abort that arrives after `runImport` has settled has no effect.
7. Without a `signal`, behaviour is 1.x's exactly.

If `onBatch` throws while an abort is pending, the run rejects with `IMPORT_FAILED` as in 1.x:
the writer's failure is the more important fact.

**`onProgress` (D3).**

1. Called at most once per batch, after that batch's `onBatch` has settled, and once more when
   the run finishes successfully. Not called after an abort, nor for a run that rejects, after
   it rejects. A plan refused before a row is read (a result with an `error` in
   `planProblems`) reports no progress: nothing was read.
2. `bytesRead` counts bytes consumed from the input. The final call has `bytesRead` equal to the
   input's size and `rowsRead` equal to the result's `rowsRead`. Values never decrease.
3. Never awaited. If it throws, or returns a promise that rejects, the error is swallowed, nothing
   is logged, and the import is unaffected.
4. A run with `signal` and `onProgress` (neither aborted) returns exactly what a run without them
   returns.

**`grouping` (D4).** Default `true`. A plan with `group` and `contiguous: true` streams as 1.1's
`grouping: true` did. `contiguous: false` is refused before a row is read with `INVALID_PLAN`, a
`PLAN_GROUP` problem with `reason: 'non-contiguous'` and `NON_CONTIGUOUS_NOT_STREAMED`.
`grouping: false` keeps 1.x's refusal (`reason: 'grouping-disabled'`, `GROUPING_NOT_STREAMED`).

## 4. Behaviour changes

### 4.1 Grouping on by default

See §2.1. A 1.x caller that relied on a grouped plan being refused passes `grouping: false`.

### 4.2 Binary input refused (D5)

The first `min(8192, size)` bytes are classified, in this order:

1. starts with `PK` → xlsx;
2. starts with the OLE2 signature `D0 CF 11 E0` → refused, `UNSUPPORTED_FORMAT`, the 1.x `.xls` message;
3. starts with a UTF-16 byte-order mark (`FF FE` or `FE FF`) → refused, `UNSUPPORTED_FORMAT`, the 1.x UTF-16 message;
4. **new:** contains a NUL byte (`0x00`) → refused, `UNSUPPORTED_FORMAT`,
   `This file is not a spreadsheet: it holds binary data. Save it as .xlsx or as UTF-8 CSV and try again.`;
5. otherwise → CSV, read exactly as in 1.x.

A NUL after the first 8 KB does not refuse the file. UTF-8 text contains a NUL only to encode
U+0000, which no spreadsheet program writes into a cell, so every CSV variant 1.x reads is still
accepted: UTF-8 with or without a BOM, each separator `detectDelimiter` knows, CRLF and LF, and
multi-line quoted cells. Every existing CSV fixture is a test of that. The same
function (`detectFormat` in `sheet-format.ts`) classifies for all five entry points, so the code
and message are identical. In Node the stream is peeked for up to 8 KB before the format is
decided; the peeked bytes are replayed to the reader.

### 4.3 `receiveUpload` enforces `idleTimeoutMs`

While the upload is being read, a request body that delivers no bytes for `limits.idleTimeoutMs`
(default 30 s) is abandoned: the upload fails with `ImportError` `TIMEOUT`
(`The upload stalled.`) and the request is destroyed, which closes the connection. Before the file
part has started, `receiveUpload` rejects; after, the file stream it returned errors with that
`ImportError`, which `runImport` and `previewSheet` reject with. Time during which the request is
paused because its reader is not pulling (backpressure from a slow `onBatch`) is not idle time.
The timer is the package's own, never `socket.setTimeout`, so nothing leaks to later requests on a
keep-alive connection.

### 4.4 `receiveUpload` enforces `maxFieldNameBytes`

A part, field or file, whose name is longer than `limits.maxFieldNameBytes` (default 200) is
refused with `TOO_LARGE`. busboy applies its own `fieldNameSize` to urlencoded bodies only, so
in 1.x a multipart part's name was never bounded.

### 4.5 Error codes

All 1.x codes stay, with their statuses. One is new:

| Code | Status | Raised by |
| --- | --- | --- |
| `ABORTED` | 499 | `runImport`, when its `signal` aborts (§2.1) |

`TIMEOUT` (408) is now raised by `receiveUpload` only: a stalled body (§4.3) or one that ends
before the file finished. `UNKNOWN_ENTITY` (404) is no longer raised by the package; it stays in
the closed set for apps whose wire uses it.

## 5. Migration

MIGRATING-2.0.md is the user-facing guide. In short:

- **Router users** write their routes from the functions. A complete Express example
  (preview, validate, import) of about 30 lines is in MIGRATING-2.0.md, compiled by the
  README-snippet check and exercised over HTTP by the consumer check.
- **Large files** move to the polling pattern: README recipe "Background imports with polling".
- **Grouped plans** now import by default. Pass `grouping: false` to keep 1.x's refusal.
- **Binary files** previously read as nonsense rows are refused with `UNSUPPORTED_FORMAT`.
- **`totalTimeoutMs`** → `signal: AbortSignal.timeout(ms)`.
- **Dynamic Entity 3.x** stays on `^1.3.0`, served by the 1.x line (`release-1.x`). Its 4.0
  adopts 2.0; the list of what it changes is in api-audit.md.

## 6. Acceptance criteria

Each is a passing test or check.

1. No export, type or doc mentions `createImportRouter` or `express`, except CHANGELOG.md and
   MIGRATING-2.0.md.
2. The main entry still has zero runtime dependencies; the `/browser` and `/node` bundle rules
   hold, each proven by a planted violation.
3. The D2 abort cases and D3 progress cases pass for CSV and xlsx, with grouping on and off.
4. `runImport` without a `grouping` option groups.
5. Binary refusal is identical across all five entry points, and every 1.x CSV and xlsx fixture
   still reads identically.
6. MIGRATING-2.0's Express example and the polling recipe compile in the snippet check, and the
   example passes an HTTP test (preview, validate, import) in the consumer check.
7. `release.yml`'s tag selection is proven for v1.x, v2 prereleases and v2 stable.
8. Dynamic Entity's drift in-range job is green throughout.
9. Every field of `ImportLimits` is enforced by an exported function, each with a test
   (`idleTimeoutMs` by `receiveUpload`).
